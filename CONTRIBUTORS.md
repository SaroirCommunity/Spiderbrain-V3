# Contributors

The list is append-only by default. Names are added by the maintainer on PR merge, with the contributor's consent on how they wish to be named (legal name, handle, or pseudonym). A contributor may request that their name be removed at any time; see "Removal" below and [`GOVERNANCE.md`](./GOVERNANCE.md).

## Adding yourself

You do not need to edit this file in your PR. The maintainer adds your entry when your PR is merged.

If your PR is merged and your name has not appeared within seven calendar days, leave a short comment on the merged PR and we will add it. Specify in that comment, or in your original PR description, how you would like to be listed:

- The display name to use (legal name, handle, or pseudonym).
- An optional link (your site, GitHub profile, ORCID, LinkedIn, anything you prefer).
- The wording of the contribution description, if you have a preference.

If none of the above are specified, the maintainer will use your GitHub display name and a brief description of the merged PR.

## Removal

You may request that your name be removed from this file at any time, for any reason (including but not limited to personal safety, employment changes, or rights of erasure under data-protection law such as the GDPR or the DPDP Act). No justification is required.

To request removal, email `contact@perform.digital` from an address associated with your contribution, or comment on any of your merged PRs with the request.

Removal applies to:

- This file (the entry is replaced with `_(contributor name withdrawn at their request)_` to preserve the chronological ordering of other contributors).
- Any doc-section footer or per-adapter README byline added in connection with your contribution.
- Future release notes referencing your contribution that have not yet been published.

Removal does not apply to:

- The Git commit history of merged PRs (an immutable record of the contribution with the authorship metadata you supplied at commit time; modifying this would require force-pushes that affect every downstream clone and is not a service we offer).
- Release notes that have already been published, which we annotate with the same `_(contributor name withdrawn at their request)_` placeholder but do not rewrite.

If you wish your Git authorship metadata to be redacted as well, this requires a coordinated effort with downstream consumers and is handled case-by-case; ask in your removal request.

## Recognition policy

Per [`CHALLENGES.md`](./CHALLENGES.md) "Recognition" and [`GOVERNANCE.md`](./GOVERNANCE.md):

- All accepted contributions earn a place in this file.
- Tier-1 first-of-kind adapter authors additionally retain first-author byline on the adapter's README until and unless a fundamental rewrite, at which point the rewriter is added as co-author and the original contributor remains credited.
- Benchmark contributions are credited inline on the rows they add to `docs/benchmarks.md`.
- Screenshot and recording contributions are credited via alt-text or image caption.
- These additional credit lines are subject to the same removal policy as this file.

Thank you for helping spiderbrain stay honest, sharp, and useful.
